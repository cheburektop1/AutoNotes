  [ Проблемное поле ] 

Существующие методы фиксации лекций неэффективны:
1. **Диктофоны** создают «линейные» файлы, в которых невозможно быстро найти нужную информацию без полного переслушивания.
2. **Ручные конспекты** часто фрагментарны: ученик отвлекается на запись формулы и пропускает объяснение учителя.
3. **Отсутствие связи** между аудиозаписью, визуальными данными (фото доски) и текстовыми заметками.

   
[ Целевая аудитория / заказчик ]
**Первичная аудитория:** Учащиеся Лицея НИУ ВШЭ и студенты вузов, посещающие лекционные занятия.
**Вторичная аудитория:** Люди, посещающие профессиональные конференции, вебинары или интервью, которым необходимо быстро фиксировать и структурировать большой объем аудиоинформации.

[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]
Продукт разрабатывается под платформу Android. К моменту сдачи он должен работать в следующей конфигурации:

Android: версия 10 (API 29) и выше
Оперативная память: от 3 Гб
Свободное место: от 1 Гб на установку (приложение и офлайн-модель распознавания речи) плюс место под записи; один час аудио занимает порядка 30–60 Мб, в зависимости от формата и битрейта
Аппаратные модули: микрофон и основная камера
Интернет: нужен только для облачной расшифровки и ИИ-конспекта; запись, маркеры, фото, воспроизведение и офлайн-расшифровка работают без сети
Для разработки: компьютер с Android Studio и смартфон на Android 10+ (желательно второе устройство для проверки)

Значения по памяти и месту ориентировочные. Подтвердите их замерами на своём телефоне после этапа 7.

[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]
Программный продукт будет предоставлять следующие возможности:

Запись аудио лекции, не прерывающаяся при погашенном экране
Маркеры в реальном времени четырёх типов («Важно», «Определение», «Пример», «Домашнее задание») с привязкой к секунде записи
Съёмка фото доски внутри приложения без остановки записи, с автоматической привязкой к текущей секунде
Текстовые заметки с временной меткой во время записи
Интерактивный плеер с таймлайном: иконки маркеров и фото, переход к нужному моменту по нажатию
Расшифровка записи (STT): офлайн (Vosk) и облачная
Краткий конспект по расшифровке и маркерам с помощью ИИ
Экспорт отчёта в Markdown и PDF (формат: «05:20 — Важное определение; [фото доски]; 12:40 — Домашнее задание»)
Список записей с переименованием, удалением и поиском по названию
Локальное хранение данных на устройстве; отправка в облако только с согласия пользователя
Вне рамок ИВР (развитие проекта): чат-бот по записи, поиск по расшифровке, облачная синхронизация

[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]
Анализ 3 продуктов, которые максимально приближены к заданному функционалу, показал, что:

Стандартные диктофоны (например, Samsung Voice Recorder): позволяют ставить закладки и записывать звук, но закладки не имеют типов, нет привязки фото доски и нет структурированного конспекта или отчёта
Google Recorder: умеет расшифровывать и искать по тексту, но не даёт размечать запись типами маркеров, не привязывает фото к таймлайну и не формирует итоговый отчёт; доступность зависит от устройства и региона
Otter и аналогичные облачные сервисы: делают расшифровку и краткое содержание, но работают через облако, ключевые функции платные, ориентированы в основном на английский язык и не дают фото-привязки


[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]

Kotlin / Android Studio: разработка Android-приложения
Jetpack Compose: пользовательский интерфейс
Архитектура MVVM, Kotlin Coroutines и Flow: логика и асинхронные операции
CameraX: съёмка фото внутри приложения
Foreground service (тип microphone), MediaRecorder и MediaPlayer (или ExoPlayer): запись и воспроизведение
Vosk: офлайн-расшифровка речи; облачный STT и LLM API (сервис выбирается после сравнения качества и доступности)
PdfDocument (встроенный API Android): генерация PDF
Git / GitHub: контроль версий
БД: Room (надстройка над SQLite), локальная база на устройстве. Таблицы: Recording, Marker, Photo, Note, Transcript; связи «один ко многим» с каскадным удалением

[ Возможные риски и пути их преодоления ]

* **Технический риск:** Высокое энергопотребление при обработке аудио.
*    Решение: Перенос тяжелых вычислений на сервер или оптимизация фоновых процессов.
* **Качество звука:** Сильный шум в аудитории мешает расшифровке.
*    Решение: Внедрение программных фильтров очистки звука или использование моделей AI, устойчивых к шуму (Whisper).
* **Финансовый риск:** Платные API могут быть дорогими.
*    Решение: Использование бесплатных библиотек с открытым кодом (Vosk/TFLite) для базовых функций.
